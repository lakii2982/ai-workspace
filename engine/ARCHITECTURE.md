# AI WorkSpace 架构设计

AI WorkSpace 把可审查的项目文件和可恢复的任务状态放在同一个本地工作空间。用户可直接阅读项目文件，Agent 通过同一套服务使用任务、检索、成果和时间线。

## 入口和数据权威

- **CLI 与 stdio MCP** 调用同一个 Python 服务。命令和工具使用同一套参数、结构化返回值和错误。安装和部分维护操作通过 CLI 执行。
- **项目资料与成果** 以工作空间的文件为准。内容指纹用于来源回读、覆盖校验和发布记录。正式发布将批准版本移交到成果目录并保存旧值。
- **任务状态** 默认保存在 `.workspace/jobs`。稳定任务 ID 连接目标、范围、进度、检查点和产物索引。派生的 HANDOFF 便于交接，恢复操作读取当前任务状态。已有飞书环境可以切换任务与项目状态权威，正文仍在本地。
- **检索** 从 Markdown、TXT、DOCX、XLSX 和文本 PDF 提取可定位片段，在 SQLite 建派生索引。调用方指定项目范围，服务在搜索与来源回读时检查范围，原件变更时要求重新确认指纹。索引刷新可扫描整个工作空间，检索结果按请求范围过滤。
- **时间线与项目 Git** 记录项目决定和可追溯的文件状态。项目可选启用独立 Git，不需要远端仓库。AIWS 用临时 index 创建观察与阶段快照，并保留在项目的专用 refs 中，用户分支与暂存区保持自己的工作状态。

## Agent 的接续流程

1. 用项目和任务 ID 恢复工作。Git 项目直接获得 `work_context`，包含概览、工作位置、相关记忆和待阅读文件。
2. 按观察版本读取相关原件，用 `mark_context_read` 记录实际读过的文件。后续发现变更会重新进入阅读队列。
3. 通过受控入口保存文件与项目事件。阶段结束通过 `save_work_checkpoint` 保存代码或文档所在状态、当前任务 revision 与下一步。
4. 下一个 Agent 从检查点恢复。完整任务迁移包含本地状态和项目 Git 目录，应使用私有备份，普通 Git 分支只携带其自身的历史。

## 一致性与部署边界

受控入口用单机文件锁协调跨进程写入。任务以 revision 比较版本，文件以 expected_hash 比较内容。工作空间依赖本机账户和操作系统权限。调用中的 scope、租约和确认字段约束工具内工作流，具有直接文件权限的调用者仍可在入口外操作。

默认部署为单机本地。飞书适配器面向已有匹配表结构、权限和单协调主机的部署。远端回执不明确时先回读和对账，恢复副本默认离线。具体参数、失败语义与数据格式见 [接口与数据契约](INTERFACE_SPEC.md)。
